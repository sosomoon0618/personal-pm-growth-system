# 资产更新门禁与验收

## 写前门禁

先明确本轮要写入的文档、Base 表、字段或关联，以及用户是否已明确确认该范围。下列情况必须先停下并提出提案：

- 新增、删除、合并核心 Base 表、核心字段、目录层级或 Skill；
- 将单次面试结论升级为全局规则、能力结论或 SOP；
- 覆盖现有事实、原始记录、PRD 或复盘正文；
- 不确定一项资料应进入项目工作材料还是个人系统资产。

以下是普通内容更新，但仍需有用户对具体写入范围的确认：新增一条证据、补全原始记录、创建已确认的行动、补充已有项目上下文卡、更新已确认的答案或链接。

## 处理判断

| 发现 | 优先处理 |
|---|---|
| 问题只是表达不清、缺练习 | 更新母题答案或建立表达练习行动 |
| 缺少项目背景、职责、数据、取舍或结果证据 | 补项目上下文卡或可复用项目证据；必要时建立工作留痕行动 |
| 某个高价值需求缺少闭环资料 | 在原项目资料下补生命周期资料；系统表只补入口、状态和个人反思 |
| 可跨项目复用的工作方法被真实使用并验证 | 先提出 SOP／模板更新提案 |
| 面试官给出明确评价 | 原样标为直接反馈，并保留适用范围；不要反推成单题结论 |
| 推测的原因或建议 | 标为复盘推断／建议，设置下一步验证条件 |

## 写后验收

逐项回读并确认：

1. 文档放入正确父级，标题能辨识对象与场次／用途；
2. Base 写入的字段类型、选项、关联记录和状态符合当前 schema；
3. 原始问答、直接反馈和复盘判断没有混写；
4. 新链接能打开，旧资料未被无授权覆盖；
5. 行动具有来源、下一步、节奏或阻塞条件；能力状态没有被提前标为“已改善”；
6. 实际变更、未完成项和新发现风险回写至本地控制文档。

## 最小验收用例

| 用例 | 输入 | 成功标准 |
|---|---|---|
| 岗位准备 | 一个 JD 或岗位方向 | 只读取相关资产，区分已证实／可迁移／缺失，并给出准备优先级；不自动写入 |
| 场次复盘 | 一场完整原始记录 | 产出整场与单题两级处理，完整问答不被摘要替代，直接反馈与推断分开 |
| 行动设计 | 一个已识别缺口 | 能判断是表达、证据、工作方法、SOP 还是长期能力问题，不机械创建训练任务 |
| 资产更新 | 一条可复用发现 | 给出最小更新对象与影响范围；单次证据不会直接修改全局规则 |
| 一致性检查 | 一组相关文档和记录 | 只报告断链、重复、状态矛盾和证据缺口；未经确认不修复 |
