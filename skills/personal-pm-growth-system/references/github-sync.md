# GitHub 受控自动同步

适用于本系统的**本地控制资产**在已获用户确认、完成写后验证之后的同步；飞书正文和 Base 仍以飞书为唯一正文，不导出到仓库。

## 可同步范围

仅允许提交以下仓库相对路径：

- `control/**`
- `skills/personal-pm-growth-system/**`
- `.gitignore`

不提交飞书导出、Base 数据、临时请求载荷、日志、凭据、令牌或其他本地工作资料。

## 自动同步门槛

1. 用户已确认本轮资产或 Skill 写入范围，且写后验收通过。
2. 已知同步仓库根目录，并先读取当前 `git status --short`。
3. 工作区若出现上述允许范围之外的已修改或未跟踪文件，停止同步并列出路径；不混合提交，也不静默跳过。
4. 同步前执行 `git diff --check`；发现空白错误即停止。

## 执行与验证

1. 在工作区干净或仅有允许范围改动时，先 `git pull --ff-only`；无法快进、发生冲突或认证失败即停止，不自动合并或变基。
2. 仅显式暂存允许范围内的变更；没有可提交变更时说明即可。
3. 使用描述本轮实际变更的提交信息创建提交，再普通 `git push` 到当前上游分支。
4. 回读最新提交、远端推送结果和 `git status --short`。只有推送成功且工作区干净，才报告“已同步”。

## 禁止操作与恢复

- 不使用 `--force`、`reset`、自动合并、自动 rebase 或清理未跟踪文件。
- 同步失败时保留本地改动，不覆盖用户内容；报告失败环节及可选的人工处理方式。
- 若用户明确要求扩大同步范围，先提出范围变更，再修改本参考和控制清单后执行。
